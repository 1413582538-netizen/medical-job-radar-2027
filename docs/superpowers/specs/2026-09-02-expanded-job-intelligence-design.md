# 扩展医疗与大健康校招情报采集设计

## 目标

将当前以单一高校就业网和少量固定公告为主的采集方式，扩展为可持续运行的“大健康相关校招岗位雷达”。系统应覆盖医疗健康主赛道，以及消费健康/美妆、医药零售和科技医疗业务线中与用户画像相关的 2027 届校招岗位。

不做岗位价值评分、自动投递或无法核实的信息补全。

## 范围

### 行业

- 医疗器械、医学影像、医疗机器人、IVD、生命科学、生物医药、创新药、CRO/CDMO；
- 医疗 AI、数字医疗、智慧医疗、医疗数据；
- 消费健康、美妆、医药零售；
- 大型科技公司中的医疗健康业务线。

### 岗位方向

- 产品、产品市场、产品工程；
- 注册法规、质量；
- 研发、算法、软件、硬件、检测与生命科学研发；
- 医学事务、医学合作、临床研究、临床运营；
- 市场、项目管理及管培生。

仅收录含有 2027 届、2027 校招、2027 秋招、校园招聘、应届生或管培生信号的近期岗位/公告；企业官网中没有明确届别时，保留为候选来源而不自动写入岗位。

## 数据来源与优先级

1. 企业官方招聘官网、校园招聘页、官方微信公众号招聘公告；
2. 可信高校就业网和企业在高校发布的招聘公告；
3. 牛客、应届生等平台用于发现岗位，并优先回链至官网；
4. 搜索引擎仅用于发现新企业与新来源，不能单独作为入库依据。

所有来源在采集前都必须通过允许域名清单。链接失效、正文无法证明招聘信息或无可验证企业归属时，记录采集错误但不写入岗位表。

## 企业库

维护可扩展的企业种子清单，每项包含企业名、行业分类、优先城市、官方招聘 URL（可为空）、备用网址来源和别名。

第一批必须覆盖：麦科田、GE Healthcare、联邦制药、雅诗兰黛、华大智造、巨鲨医疗、字节跳动（医疗业务）、阿里健康、华润及其医疗健康业务、科大讯飞（医疗业务）。

企业库只是发现入口，不等同于岗位数据。只有实际可核实的招聘记录才能写入 `companies` 与 `jobs`。

## 采集流程

```text
企业种子与动态关键词
  -> 官方招聘页抓取/高校公告检索
  -> 2027 届与岗位方向过滤
  -> 规范化公司、行业、地点和来源字段
  -> 官网链接回填与来源优先级合并
  -> 去重写入 Supabase
  -> GitHub Pages 重新构建发布
```

每个来源模块仅负责“发现并输出候选记录”；规范化、验证、去重和写库继续集中在现有公共模块中，避免各来源产生不同的字段规则。

## 合并与展示

- 去重顺序：官方招聘 URL、来源岗位 ID、来源公告 URL、公司+岗位名称+地点；
- 相同岗位的多来源记录合并为一条，以官方链接、官方来源名称和已验证字段为准；
- Dashboard 保持“一家公司一行”，汇总该公司的岗位标题、行业、地点和最优招聘链接；
- 增加消费健康/美妆、科技医疗业务的筛选值，现有筛选兼容。

## 失败处理与可观测性

- 某一来源抓取失败不能阻止其他来源入库；
- `crawl_logs` 记录来源错误、候选数量、新增岗位数和新增公司数；
- 无法确认的公司性质、规模、地点、发布时间或介绍使用 `未知`，不推断；
- 每周六北京时间 10:00 的工作流运行，完成后触发静态站点部署。

## 测试与验收

- 为企业种子、来源允许域名、招聘届别判断、岗位方向判断、官网优先合并、公司合并展示分别建立自动化测试；
- 新增来源模块应有 HTML/JSON fixture 测试，不能依赖实时网络；
- 运行完整测试、静态构建，并在公开 GitHub Pages 地址验证：页面可访问、筛选存在、每公司只展示一行、招聘链接可见；
- 首批数据验收包含用户列出的十家企业中可公开核实的岗位或官方招聘入口；若某企业暂无 2027 校招，Dashboard 不伪造岗位，并在采集日志保留检查结果。
